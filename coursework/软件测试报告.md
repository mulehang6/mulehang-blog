# Mulehang Blog 软件测试报告

## 前言

### 1. 项目简介

本次课程设计选择的被测系统为 `Mulehang Blog 博客内容管理系统`。该系统是一个基于 `Spring Boot 3.5.9 + Java 21 + Vue 3 + TypeScript + Vite` 的前后端分离 Web 应用，包含用户注册登录、文章发布、文章管理、评论互动、分类标签管理、搜索与 AI 辅助写作等功能模块。

项目具备完整的网站页面、数据库增删改查能力与 REST API 接口文档，满足课程设计“编写并部署一个网站，并对其进行功能测试、自动化测试、性能测试和兼容性测试”的基本要求。

## 缺陷记录与问题分析

### 5.1 已发现问题

在本次测试实施过程中，发现并修复了两个真实问题：

| 问题编号 | 模块 | 问题描述 | 影响 | 处理结果 |
| --- | --- | --- | --- | --- |
| BUG-01 | 登录态恢复 | 整页刷新或直接访问受保护页面时，路由守卫先执行，Pinia 内存态丢失，用户会被错误重定向到登录页 | 影响登录后访问文章管理页等受保护页面 | 已修复 |
| BUG-02 | 登录异常提示 | 后端登录失败时抛出通用运行时异常，前端只能收到“服务器内部错误”，无法展示“用户名或密码错误”等业务提示 | 影响用户定位登录失败原因，也不利于接口语义一致性 | 已修复 |

### 5.2 问题说明

问题说明如下：

1. `BUG-01` 的根因在于前端登录态仅保存在内存中，刷新页面后状态丢失，且请求层未稳定注入持久化令牌。后续通过 `sessionStorage` 持久化令牌、请求拦截器补充 `Authorization` 头，以及路由守卫先恢复会话再做权限判断的方式修复。
2. `BUG-02` 的根因在于后端将“用户名或密码错误”这类用户可见业务异常以通用 `RuntimeException` 抛出，而全局异常处理把它统一包装为“服务器内部错误”。后续通过改为抛出 `IllegalArgumentException` 并在全局异常处理中保留明确业务消息的方式修复。
